Architecture Overview

This project demonstrates a cost optimized AWS cloud architecture built to understand scalability, high availability concepts, and cost control using Free Tier eligible services. The architecture is intentionally simple but follows real world cloud design principles.

VPC Design
A custom Virtual Private Cloud is created with a dedicated IPv4 CIDR range. The VPC provides logical isolation for all AWS resources used in this project. Keeping a single VPC reduces complexity and avoids unnecessary networking cost.

Subnet Design
One public subnet is created inside the VPC. All resources are placed in this subnet to eliminate the need for additional networking components such as NAT Gateway. Public IP assignment is enabled so EC2 instances can directly access the internet.

Internet Gateway
An Internet Gateway is attached to the VPC. This allows inbound HTTP traffic from users and outbound internet access for EC2 instance updates and package installation.

EC2 Compute Layer
A single EC2 instance is launched using t2.micro or t3.micro instance type to remain within Free Tier limits. The instance runs an Apache web server that serves a simple web page. The default EBS root volume is used for operating system and application storage to avoid extra storage costs.

Application Load Balancer
An Application Load Balancer is placed in front of the EC2 instance. It handles incoming HTTP requests and forwards traffic to the target group. Health checks are enabled to monitor instance availability. The load balancer is created mainly to understand traffic routing and load balancing behavior and is deleted after testing to control cost.

Auto Scaling Configuration
An Auto Scaling Group is configured using a Launch Template. Minimum, maximum, and desired capacity are all set to one. This setup demonstrates Auto Scaling concepts such as health monitoring and instance replacement without launching additional instances that would increase cost.

AMI Strategy
A custom Amazon Machine Image is created from the configured EC2 instance. This AMI is used in the Launch Template to ensure consistent deployments and faster recovery in case the instance needs to be replaced. Using AMIs reduces manual configuration time and improves reliability.

Security Configuration
Security Groups are configured to allow inbound HTTP traffic on port 80 from the internet. SSH access on port 22 is restricted to a specific IP address to reduce security risk. Outbound traffic is allowed to enable system updates and package downloads.

Cost Optimization Approach
Only Free Tier eligible services and instance types are used.
Auto Scaling is restricted to a single instance.
No NAT Gateway, additional subnets, or paid services are used.
Resources are stopped or deleted immediately after learning objectives are met.

Design Goals
Understand core AWS architecture components.
Learn how scalability works without increasing cost.
Practice cost conscious cloud design decisions.
Build a real world architecture suitable for beginner cloud and DevOps roles.
